## 1. 口径原则

1. **单一事实源**：一个定义只在一处实现，下游只读产物，不重算。
2. **分层判定 + 固定优先级链**：四类数据源各自判定，跨源冲突按固定顺序解决——
   **新用户 → 滑动窗口三态 → 回流名单 → RFM 类型 → 一般用户**。
   - 新用户 / 回流 → `recent_user_segments/*_7d.csv`
   - 是否/曾经高价值活跃 → 滑动窗口 180 天轨迹（`sliding_windows/high_value_active_periods.csv`）
   - 近期活跃度与价值档位 → RFM（`user_behavior_rfm_segments.csv`）
   滑动窗口代表**当前价值状态**、回流名单代表**时序身份**，前者优先；否则当天仍在高价值活跃的用户会被标成「回流用户」，发券时拿错券。
3. **单层互斥**：最终只输出一个 `最终分群` 列，命中即停，不允许多值。
4. **全集以 90 天活跃用户为准**：307,950 人（最近充电时间 2026-04-20 ~ 2026-07-19）。
5. **滑动窗口回看跨度固定 180 天**（91 个窗口）：全量历史（数据自 2020-01-01 起）计算量过大，暂不启用。
6. **身份与附加条件分离**：分群只切「身份 / 生命周期」一根轴；券、谷段、异常等业务条件一律走附加条件列，不参与落桶、不计入合计、不改变总人数。

- 互斥机制：同源桶天然互斥（滑窗 4 态 / RFM 类型均为单值），跨源桶由优先级链强制。互斥是设计保证，不依赖数据巧合。

### 4.1 回流用户的两类划分

回流名单（距上次充电 > 30 天、近 7 天重新充电）共 9,397 人（v0.8 名单已同源，等于主表内人数），按「180 天内有没有出现过高价值活跃窗口」一刀两断：

| 类 | 判定 | 人数 | 落位 |
| --- | --- | --- | --- |
| 曾是高价值活跃 | 180 天内至少一个窗口表现为高价值活跃 | 665 | 被滑窗三态吸收：稳定 95、回流高价值 34、历史高价值活跃 536 |
| 回流非高价值活跃（NHV） | 180 天内没有任何一个窗口表现为高价值活跃 | 8,732 | 02 桶，与 NHV 定义完全等价 |
| 合计 |  | 9,397 |  |

- 判据与滑窗桶的判据是同一个（是否出现过高价值活跃窗口），因此天然自洽，不需要额外匹配「断档前充电日期落在哪一段」。
- 滑窗本是四态，第四态「沉默高价值活跃」要求近 90 天完全没充电，而回流用户近 7 天刚充过电，物理上不可能落在这一态，所以这里只会出现三态。
- **两套标记不得混用（v0.8 实测）**：`returning_users_7d.csv` 自带的 `断档前是否高价值活跃用户` 列给出 409 人（配套 `断档前高价值活跃状态` 全部写作「是」），判据是「**上次充电日期**落在某个高价值活跃段内」；而 4.1 的 665 人判据是「180 天内**出现过**高价值活跃窗口」。两者相差 256 人（出现过、但断档点不在段内）。02 落桶只认 665 口径，该列仅作回显（见 5.3），**不得用于落桶或发券取数**。
- **落桶用列（9/21 起）**：`returning_users_7d.csv` 新增 `180天内是否出现高价值活跃`（是 / 否）与 `180天内高价值活跃状态`（稳定 / 回流 / 历史高价值活跃（当前已退出） / 空，来源即 `high_value_active_periods.csv` 的四态）。**02 = 回流名单中该列 = 否**；该列 = 是 的 665 人被 03/04/05 吸收，落桶时不再需要任何二次匹配。

## 5. 附加条件与辅助列（均不进主枚举）

### 5.2 策略分项口径（优惠依赖度 / 谷段偏好度）

**样本门槛（必须）**：`订单总数 < 3` 一律输出 `样本不足`。

理由：1 单用户在低频低价值桶占 75%、一般用户桶占 67%、新用户桶占 90%，其 `优惠使用率` 与 `平均谷段电量占比` 只能取 0 或 1，属于噪声。不加门槛时，新用户桶会出现 3,125 个「高优惠使用率」，加门槛后只剩 72 个。

| 分项 | 高 | 中 | 低 | 样本不足 |
| --- | --- | --- | --- | --- |
| 优惠依赖度 | 优惠使用率 >= 0.5 | 0.2 <= 值 < 0.5 | < 0.2 | 订单总数 < 3 |
| 谷段偏好度 | 平均谷段电量占比 >= 0.5 | 0.25 <= 值 < 0.5 | < 0.25 | 订单总数 < 3 |

备用档：`>= 0.8` 作为「极高」，需要时另出一列，不要替换主档。

**与 `价格敏感等级` 的关系（必须写清）**：现有 `价格敏感等级`（`build_user_behavior_features_pipeline.py:1532`）的判定是
`高价格敏感 = 优惠使用率 >= 0.5 或 平均谷段电量占比 >= 0.5`（102,361 人），即**两个分项的并集**。
因此三者不是独立维度：`价格敏感等级` 是综合标记，两个分项是它的拆分。下游不得把三者当独立特征使用。

**为什么必须拆开**：实测两者并不重合——「谷段高但券使用率低」的人数是「券高但谷段低」的近 2 倍（订单数 ≥ 3 口径：03 桶 991 : 463、05 桶 2,414 : 1,246）。合并成一个「价格敏感」会丢掉这个区别，而两者对应完全不同的动作：前者适合错峰/谷段权益，后者适合券与防薅羊毛。

## 6. 边界人群

### 6.1 沉默高价值活跃（848 人，分群第 10 类）

- 定义：180 天滑动窗口内至少一个窗口表现为高价值活跃，且近 90 天完全没有充电。
- 与第 05 类「历史高价值活跃用户」的关系：**两者互斥**，区别是近 90 天是否仍有充电——第 05 类必须显式限定「近 90 天仍有充电」（滑窗「历史已退出」态 18,924 人，其中 19 人因新用户优先级被 01 吸收，落桶后 05 = 18,905），否则会被本类完全包含。
- 四态合计（互斥且完备）：稳定 5,387 + 回流 2,566 + 历史高价值活跃 18,924 + 沉默高价值活跃 848 = 27,725，即全部曾高价值活跃用户。

- 处理：**定义上列为分群第 10 类，但输出时单独出一份名单，不并入主表**。并入则全集改为 90 天活跃 ∪ 曾高价值活跃（180 天），总数 307,950 → 308,798（建议命名「运营全集」）。

- **边界对齐（1 人差）**：滑窗的「近 90 天」是**日期口径**（末窗口 = 2026-04-21 ~ 2026-07-19），主表是**时间戳口径**（末次充电时间 − 90 天 = 2026-04-20 23:57:45 起）。两者差 1 人（`257897551`，末次充电 2026-04-20 23:59:39：在主表内、不在末窗口内，且非高价值活跃），所以末窗口 307,949 人 vs 主表 307,950 人属正常边界差，不是口径错误。

### 6.2 口径冲突用户（6,723 人）

- 现象：RFM 判「高价值活跃用户」，滑动窗口 91 个窗口全程判「一般用户」。
- 实测画像：订单总数 100% 为 1；滑动窗口最后一个窗口类型 100% 为「一般用户」；R=1、F=1 或 2、M=4 或 5。
- 根因：9/7 快照使用旧 F 规则（无 14 天下限），单订单用户 F=1 被判高价值活跃；当前代码 `GREATEST(..., 14)` 会得 F=3。
- 分群归属（实测）：新用户 5,783 人（在 `new_users_7d.csv`）、回流用户 930 人（在 `returning_users_7d.csv`），其余约 10 人。**不需要单独的降级动作**，第 4 节的优先级 01/02 会自动吸收他们。
- 真实首充（按 2020-01-01 起全量历史核对）：首次充电落在最近 7 天的 4,318 人；首次充电早于 2026-04-21 的老用户 2,398 人。
- 处理：**不新建分群桶**（属 bug 产物，修复重跑后自然散掉）；如需运营，用辅助列 `单次高消费标记`（订单总数 = 1 且 M分数 >= 4）捞取，另加 `口径冲突标记 = 是` 供对账。

### 6.3 时间窗外用户（182,696 人）
